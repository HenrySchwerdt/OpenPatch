# Living process: keeping the regulatory evidence current "on the go"

> Test project, not a medical device; water only. The idea: we write everything we can deliver while we build, so that a future legal manufacturer inherits a **current, traceable evidence set** rather than a pile of stale documents. The cost-heavy parts (labs, studies, QMS, notified body) wait for a manufacturer.

## 1. Rules for every pull request

A PR that changes any of the following **must** update the listed regulatory item in the same PR.

| If the PR changes | Update |
|---|---|
| a hazard, a safety limit, a diagnostic code or its hazard/test tag (`docs/02-safety.md`, spec §7/§7a, `docs/06-diagnostics.md`, `spec/diag-codes.csv`) | `RISK/trace-links.csv` if a link changed; regenerate `RISK/TRACE.md` with `trace.py`; `RISK/02-hazard-analysis.md` text if the hazard changed; STATUS entry if a limit relaxed |
| a requirement in `spec/design-parameters.md` | `SOFTWARE/03-requirements.md` row, GSPR row if affected |
| Cargo.lock, Package.resolved, a toolchain or a third-party binary | run `soup.py`; evaluate new/changed SOUP; commit `SOUP.md` / `soup.json` / `soup-licences.json` |
| CAD, PCB, renders, drawings | run `collect_figures.py`; regenerate affected figures; re-run `mechanical/sim/run_all.py` |
| a test or a sim scenario or a bench procedure | `RISK/trace-links.csv` verification column; `TECHNICAL-FILE/06-verification-validation-index.md` |
| a standard or regulation fact | `ROADMAP.md` / `STANDARDS-MATRIX.md` with source and date; mark **[VERIFY]** if not confirmed |
| security-relevant code or protocol | coordinate with `security/`; update `CYBERSECURITY/README.md` map |
| the intended use or labelling | **do not write it**; both are the legal manufacturer's (hard rule, no IFU, no on-body content) |

## 2. Definition of done (for a unit of work)

1. All tests green (`cargo test --workspace`, `swift test`, `check.py`, `sim`).
2. `python3 regulatory/tools/trace.py` exits 0 (no broken links); new gaps are explained in the PR.
3. `python3 regulatory/tools/soup.py --check` exits 0.
4. GSPR checklist status and V&V index updated where evidence changed.
5. `docs/STATUS.md` updated; Conventional Commit; push (repository rules).
6. No statement implies approval, safety for use on a person, or a medical claim. No insulin or other drug appears in any test plan (water only).

## 3. CI

A draft workflow is in `tools/regulatory-ci.yml` (copy to `.github/workflows/` to activate): runs `trace.py --report` and fails on errors, `soup.py --check`, `collect_figures.py --check`, and verifies that the committed `TRACE.md` equals a fresh run (stale generated files fail). The trace tool reads `spec/diag-codes.csv` when present (generated by the diagnostics work package) and otherwise parses the catalogue tables in `docs/06-diagnostics.md`.

## 4. Versioning of the technical file

- The technical file set is versioned with the repository release: **`tf-X.Y.Z`** equals the repository tag `vX.Y.Z`. First set: **`tf-0.1.0-beta`** with the 0.1.0 beta release.
- On release: regenerate `RISK/TRACE.md`, `SOFTWARE/SOUP.md`, `figures/INDEX.md`; snapshot the GSPR checklist status and the gap list into the release notes; archive the set (git tag is the archive).
- A legal manufacturer **forks the tag** as its controlled baseline, assigns its own document numbers and approvals, and from then on owns the file (QMS document control).
- Changes after release: a change request linking hazard, requirement, test and SOUP effect (`SOFTWARE/06-problem-resolution-and-configuration.md`).

## 5. Roles in the open project

| Role | Responsibility |
|---|---|
| Maintainers | merge rule: DoD above; keep disclaimer wording |
| Diagnostics work package owner | `spec/diag-codes.csv`, `docs/06-diagnostics-trace.md` |
| Security owner (`security/`) | threat model, SBOM, scorecard, vulnerability policy |
| Regulatory contributors | `regulatory/`, with sources and **[VERIFY]** flags; never intended-use or IFU text |

## 6. Review cadence

Monthly: re-check `ROADMAP.md` facts (regulations change: MDCG 2021-24 Rev. 1 and the FDA cybersecurity guidance were both revised within the last year), the standards list (harmonised standards decisions), and the gap table.
