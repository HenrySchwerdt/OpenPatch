# OpenPatch virtual pod: simulation report

> TEST PROJECT. Not a medical device, never to be worn (see `DISCLAIMER.md`). This report is
> GENERATED by `opsim report`: the tables are computed by the simulator, the prose lives in
> `openpatch-sim/src/report_text.rs`. Edit it there.

## 1. What this is, and what it is not

`openpatch-sim` runs the real `openpatch-core` (delivery engine, safety supervisor, reservoir, event
log, two-pod logic, draw mode, protocol dispatcher) on a virtual pod: a physics model behind the core's
`Hal` trait with a deterministic, seeded clock. The firmware application layer around the core
(boot, restore from flash, 1 s safety tick, persistence policy of `openpatch-bench/src/safety.rs`) is
re-implemented in `src/device.rs` because the real one needs Embassy and an nRF52840.

What it can do: replace hardware orders with questions. Does an occlusion alarm in time? Does a
dock loss mid bolus stop the motor? What does a firmware hang cost before the TPL5010 cuts the
supply? Which tolerances dominate dosing accuracy? Which bench measurement has to be made first?

What it cannot do: prove anything about real silicone, real motors or real water. Every number
here is "the core's logic on THIS plant". The plant parameters that are not in `spec/` are
assumptions (section 3); the Monte Carlo spreads them, but a population drawn from a wrong centre
is still wrong. Treat a result as "the logic is capable of this", and treat a surprise as
"measure this on the bench before you trust the logic".

The model is quasi-static (inertia neglected, 5 ms steps), a step is lost when the load torque at the
rotor exceeds the pull-out torque at that step rate and supply voltage, and a lost step stays lost.
It has no thermal, viscosity, resonance or RF model.

## 2. Structure

```
 scenario (TOML/JSON)  ->  Runner  ->  Device (boot, 1 s tick, persistence policy, phone via the
                                        real protocol path)  ->  openpatch-core Pump<SimHal>
                                                                     |
              World: clock, supply + battery, TPL5010, interlock gate, dock hall, angle sensor, flash
                                                                     |
              Plant: stepper -> gearhead -> backlash -> gear pair -> backlash -> M1.6x0.35 leadscrew
                     -> carriage --(axial spring)--> plunger (stick-slip seal) -> stadium reservoir
                     -> compliance + bubble -> duckbill -> needle/cannula (+ occlusion) -> tissue
```

Everything the core sees goes through `Hal`: `motor_step` (a blocking burst that advances the clock
by `steps / rate` and returns the pulses produced, 0 if the interlock does not give VMOT),
`motor_step_reverse`, `motor_enable`, `angle_read` (13 bit TMAG5273 sample decimated to 12 bit and
unwrapped exactly like `hal/angle.rs`, polled every 20 ms during a burst), `motor_current_peak_ma`,
`docked`, `battery_mv`, `watchdog_kick`, `time_ms`, `buzzer`.
The interlock is `VMOT = MCU_EN AND watchdog latch AND (DOCKED OR DIR_REVERSE)`; the TPL5010 clears
the latch and resets the MCU when no DONE arrives within its period (2 s).

Each scenario in `scenarios/*.toml` is also a `cargo test` (`tests/scenarios.rs`); the Monte Carlo
distributions below are asserted loosely in `tests/montecarlo.rs`.

## 3. Assumptions (everything not taken from `spec/`)

| item | value | basis |
|---|---|---|
| reservoir, leadscrew, motor, gear ratio, efficiencies | spec 3, 4 (74.6 mm^2, M1.6 x 0.35, NFP-608-26.45, 15:12, 1.6 gf*cm, gearhead 0.64, screw 0.20) | spec |
| pull-out torque vs step rate | spec value valid at 200 Hz, corner 500 Hz (0.69 x at the 600 Hz draw rate) | ASSUMPTION (back-EMF, `architecture.md`) |
| supply | full torque >= 3.3 V, linear down to nothing at 1.8 V | ASSUMPTION (chopper current limit, STSPIN220 VS min) |
| motor current sense | free 70 mA, stalled 175 mA, linear in load, noise 3 mA; core threshold 140 mA x 3 bursts | ASSUMPTION; the 140 mA is itself a "placeholder" in `limits.rs` |
| seal friction | static 1.5 N, dynamic 0.8 N | ASSUMPTION (spec: "biggest development risk") |
| carriage -> plunger stiffness | 40 N/mm | ASSUMPTION; dominates lost motion and the volume soaked up before an occlusion alarm |
| backlash | 2.0 deg gear pair at the screw + 1.5 deg gearhead output | ASSUMPTION |
| lead error | 0 % nominal, +-0.2 um once per turn | ASSUMPTION (tolerance sampled by Monte Carlo) |
| fluid compliance | 0.05 ul/kPa + isothermal air (bubble, connector air) | ASSUMPTION |
| duckbill | cracks at 3 kPa (spec: 1 .. 5), closes at half of it | spec + ASSUMPTION |
| tissue back pressure | 1 kPa | ASSUMPTION |
| needle + cannula resistance | 0.6 kPa per mm^3/s (30G x 10 mm, Hagen-Poiseuille); fill needle 0.4 | calculation |
| vacuum after a draw | air creeps in through the outlet with tau = 30 s (the reason for the mandatory prime) | ASSUMPTION |
| connector air to purge | 1.5 ul | ASSUMPTION |
| TMAG5273 | 13 bit, 0.1 deg rms noise, 0.5 deg once-per-turn nonlinearity, 12 bit in the HAL | datasheet class + ASSUMPTION |
| battery | 25 mAh, 1.5 ohm internal resistance, PCM cut-off 2.5 V, quiescent 100 uA | spec 1b / 5 + ASSUMPTION |
| TPL5010 | resets 2.0 s after the last DONE; boot 300 ms | `architecture.md` |
| flash | 90 ms per record write, A/B atomic (a torn write keeps the previous copy) | `architecture.md` + ASSUMPTION |
| persistence policy | constants copied from `openpatch-bench/src/config.rs` (reservoir +64 steps, wear +600 s, event ceiling +64) | copy, keep in sync |

Not modelled: temperature, fluid viscosity and degradation, motor resonance and inertia, cannula
kinking physics beyond a resistance factor, RF / BLE timing, Qi charging, the SMA drive.

Bench measurements that would replace the most influential assumptions, in order of leverage:

1. Force versus displacement of carriage + plunger + seal (static and dynamic break-away, stiffness).
   Sets lost motion, small-dose lumping and the water soaked up before an occlusion alarm.
2. Motor current versus load at 200 Hz and 600 Hz (`CsvRow` has no current column yet: see
   `architecture.md`). Sets whether the 140 mA threshold has margin for forward delivery AND draw.
3. Thrust of the geared drive at 200 / 600 Hz and 3.3 .. 4.2 V.
4. Pressure-volume curve of the closed reservoir (compliance, bubbles).
5. TPL5010 timing on the scope (WAKE / DONE / RSTn) and the VMOT collapse time.

water that really left the outlet (gravimetric equivalent), `core` what the pod booked as delivered.

seal and arm elasticity, about 0.4 U with the assumed stiffness), so a few percent of

## 5. Monte Carlo

1000 runs per experiment (`opsim report --runs N`), seed fixed, independent of the thread count.
Each run draws a new pod from the tolerances below, performs a standard refill + prime, and then
runs the experiment through the real protocol path.

| quantity | distribution |
|---|---|
| lead error (systematic) | normal, sd 0.5 %, truncated at 3 sd (+-1.5 %) |
| lead error (once per turn) | uniform 0 .. 0.5 um |
| gearhead ratio | normal, sd 0.3 % |
| stadium area | normal, sd 0.5 % (nominal 74.6 mm^2) |
| seal static friction | log-normal, median 1.5 N, sigma(ln) 0.3 |
| seal dynamic / static | uniform 0.4 .. 0.7 |
| carriage -> plunger stiffness | log-normal, median 40 N/mm, sigma(ln) 0.3 |
| gear pair backlash (at the screw) | uniform 1 .. 3 deg |
| gearhead backlash (at its output) | uniform 0.5 .. 2.5 deg |
| TMAG5273 noise | uniform 0.05 .. 0.25 deg rms |
| TMAG5273 once-per-turn nonlinearity | uniform 0 .. 1 deg |
| fluid compliance | log-normal, median 0.05 ul/kPa, sigma(ln) 0.4 |
| duckbill cracking pressure | uniform 1 .. 5 kPa (spec 1 .. 5) |
| motor pull-out torque | normal, sd 8 % (nominal 1.6 gf*cm) |
| screw efficiency | uniform 0.15 .. 0.25 (spec ~0.20) |
| air bubble in the reservoir | exponential, mean 3 ul, capped at 20 ul |
| air in the connector | uniform 0.5 .. 2.5 ul |


### 5.1 Delivery accuracy

Zero basal, a 1 U warm-up bolus (takes up the lost motion of the refill; reported separately), then
10 x 0.05 U and 6 x 1 U five minutes apart and one 10 U bolus. Per bolus the fluid that leaves the
needle within the bolus time plus 60 s is compared with the command (the gravimetric test of
`docs/02-safety.md` section 3 step 1 on a perfect balance).

Runs: 1000 (seed 20261119), failed set-ups: 112 [("draw ended in state 3", 112)]. Mean seal static friction / screw efficiency / pull-out of failed vs good pods: 2.10 N / 0.170 / 1.52 gf*cm vs 1.51 N / 0.204 / 1.61 gf*cm.

| bolus | n | mean err % | sd % | 5th % | 50th % | 95th % | worst % | within +-5 % | within +-10 % | mean err mU | sd mU |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 0.05 U | 8880 | -0.18 | 50.74 | -100.00 | 1.23 | 76.93 | 301.8 | 13.2 % | 21.7 % | -0.09 | 25.37 |
| 1 U | 5328 | -0.11 | 2.47 | -4.06 | -0.23 | 4.19 | 17.6 | 94.4 % | 99.9 % | -1.07 | 24.72 |
| 10 U | 888 | 0.02 | 0.79 | -1.30 | 0.04 | 1.37 | 2.7 | 100.0 % | 100.0 % | 1.78 | 79.47 |

Series: 10 x 0.05 U cumulative error -0.89 mU mean (sd 27.16, 5th..95th -39.1 .. 41.9); 6 x 1 U series -0.11 % mean (sd 0.86).

First 1 U bolus after a refill + 0.3 U prime (lost motion of the draw reversal): mean error -348 mU, 5th..95th -725 .. -83 mU, worst -1000 mU.


Reading the table: the spec bench target is +-5 % from 1 U. A 0.05 U dose is 8 pulses; one pulse is
12 %, and stick-slip releases the stored seal elasticity in lumps, so single 0.05 U doses are NOT
accurate (5th and 95th percentile far outside +-20 %) even though a series of them sums out. Evaluate the
0.05 U gravimetric test cumulatively, not per dose.

## 6. Findings

The simulator does not fix the core. Every behaviour that violates the safety concept is an
`#[ignore]`d, currently failing test in `tests/findings.rs` with the description in its doc comment
(`cargo test -p openpatch-sim --test findings -- --ignored`):

| test | topic |
|---|---|
| `unplanned_reset_of_an_active_pod_announces_itself` | F1: no alarm after a brown-out / watchdog reset (H3) |
| `resume_after_a_reset_without_a_schedule_is_refused_or_delivers` | F2: schedule not persisted, Resume succeeds and delivers nothing |
| `reservoir_margin_does_not_accumulate_across_reboots` | F3: reservoir margin re-added on every boot (platform policy) |
| `a_standard_prime_after_a_draw_purges_the_connector` | F4: prime smaller than the lost motion after a draw |
| `a_high_friction_pod_can_still_refill` | F5: draw current criterion has no tolerance margin |
| `the_needle_never_sees_more_than_15_u_in_an_hour` | F6: the 15 U/h cap limits the commanded, not the delivered volume |

## 7. Reproduce

```sh
cd firmware-rs
cargo test -p openpatch-sim                       # all scenarios, hardware, physics, Monte Carlo
cargo test -p openpatch-sim --test findings -- --ignored   # the open findings (they fail)
cargo run --release -p openpatch-sim --bin opsim -- all --outdir /tmp/opsim
cargo run --release -p openpatch-sim --bin opsim -- run wear_48h --csv wear.csv
cargo run --release -p openpatch-sim --bin opsim -- mc accuracy --runs 1000 --seed 1
cargo run --release -p openpatch-sim --bin opsim -- report --runs 1000 --out openpatch-sim/REPORT.md
```
