# Bootloader v2: manifest format 2, rollback protection, USB DFU rules (cup v4)

> Supplements `bootloader.md`. `openpatch-boot-policy` (host tested, real Ed25519 / SHA-512) holds every rule; the bootloader only supplies flash reads, salty and the UICR words.

* **Manifest (84 bytes):** `magic | format 2 | reserved | image_len | security version | hw_id | signature`. The signature is Ed25519 over `SHA-512("OPFW2" || 20 header bytes || image)`: version, hardware id and length are signed. Format 1 is refused. `scripts/sign-image.sh` needs `SECURITY_VERSION`; `sigtool sign <keys> <image> <prefix> <version>`.
* **Verify before swap:** manifest, key present, size, hardware id, rollback version, then the signature (cheap checks first). Without a compiled-in key everything is refused. An invalid pending update is cancelled.
* **Rollback:** the minimum security version lives in `UICR.CUSTOMER[0..32]` (one word per raise, 32 raises in the life of the chip, bits only 1 -> 0). It is raised only at a boot whose state is confirmed (`mark_booted` done, no swap or revert pending), so a reverted trial image never raises it. A damaged counter refuses updates (fail closed) and still boots the active image. Use a security version per release that must not be downgraded, not per build.
* **Application:** `dfu::finalize` only arms the swap (`mark_updated`); the bootloader verifies.
* **USB DFU transport:** `openpatch_boot_policy::dfu::DfuReceiver` (sequential blocks, bounded size, manifest last, never arms) is host tested. The USB class glue (embassy-usb + DFU class, the reserved `usb-dfu` feature of `openpatch-bootloader`) is NOT written: it cannot be built or tested here. The bootloader never enables the motor supply, so DFU mode cannot move the motor.
* **Bootloader write protection (ACL, 2026-11-24):** right before the jump to the application the bootloader configures the nRF52840 ACL peripheral so that the bootloader code `0x0000_0000..0x8000` is write- and erase-protected (PERM.WRITE disabled, READ allowed) until the next reset (the ACL registers are write-once, cleared only by a reset). Plan, alignment / size / overlap rules and the register values are in `openpatch_boot_policy::acl` (host tests `openpatch-boot-policy/tests/acl.rs` against the real layout); the bootloader only writes ADDR, SIZE, PERM and reads them back. Source: nRF52840 Product Specification, section "ACL - Access control lists" (docs.nordicsemi.com, read 2026-11-24, no revision shown on the page): base `0x4001_E000`, 8 regions, page-aligned ADDR, SIZE a multiple of the page and at most half the flash, write-once, violation = blocked + BusFault; bit positions WRITE = 1, READ = 2 from `nrf-pac` 0.4.0 (the page text does not print them).
  * **Not protected, by design:** the embassy-boot STATE page (the application writes it for `mark_booted` / `mark_updated`; the policy refuses to protect it, `AclError::AppWritable(State)`; a rogue write can only cause a verified swap or a revert to the previous signed image), ACTIVE / DFU / STORAGE (application areas), and the rollback counter in `UICR.CUSTOMER` (outside the code flash, not covered by the ACL: an application could clear bits, which makes the counter `Corrupt` = updates refused, or erase the UICR with `ERASEUICR`, which resets the minimum version). Read protection of the bootloader is refused (the code still runs the jump).
  * A plan error or a read-back mismatch does not stop the boot (no brick); TODO(verify-on-hardware): PERM read-back, BusFault on a write / erase of a bootloader page from the application, whether `ERASEUICR` / `ERASEALL` are blocked by an active region.
  * New bootloader feature `board-cup-v4` (no TPL5010 DONE path: on the cup board the TPL5010 watches the supervisor): `cd openpatch-bootloader && cargo build --release --no-default-features --features board-cup-v4`.
